# v1.4.0 — Implementation plan

Status: **implemented, not yet committed** (2026-10-13) — sections 1–8 done; items under "Deliberately not done" remain open
Base: v1.3.0 (local only — GitHub currently holds v1.1.3)

## Guiding principle

Every chat line the game writes is still **displayed** — header, original text and a
translation line. Nothing in this release hides messages or silently drops content.
Where translation is skipped or unavailable, the reason is shown in the translation line.
Any rule that would skip translation based on a guess about the content is either left
out or opt-in.

## 1. Game log location (critical)

Star Conflict moved its profile and logs from `Documents\My Games\StarConflict\logs`
to `%LOCALAPPDATA%\Targem\StarConflict\logs` (first seen 2026-10-09). v1.3.0 still
defaults to the old folder, so it watches a stale `chat.log` and shows no error.

- `_get_default_logs_path()` checks the new location first, then the legacy one. If
  neither exists, it returns the new location.
- One-time migration at startup: if the saved `game_logs_path` is exactly the legacy
  default **and** the new folder holds a newer session, switch to the new folder, save
  the setting and print an info line in the chat. A custom path chosen by the user is
  never changed.
- Status bar: if the logs folder has no `chat.log`, say so instead of the static
  "Processing chat.log...".

## 2. Translation errors: clear, short messages

Today a quota error prints the full request URL (with the URL-encoded message) into the
chat on every line. Changes:

- Errors are classified centrally (`_classify_translation_error`):
  | Kind | Detected by | Chat translation line |
  |---|---|---|
  | `quota` | HTTP 429, or `MYMEMORY WARNING … FREE TRANSLATIONS` | `[not translated – daily limit reached]` |
  | `network` | connection error / timeout | `[not translated – translation service unreachable]` |
  | `too_long` | `QUERY LENGTH LIMIT EXCEEDED` | `[not translated – message too long for the free service]` |
  | `other` | anything else | `[not translated – translation error, see App Log]` |
- Full technical details go to `app.log` only.
- The original message is always displayed above the translation line (unchanged).

## 3. Quota pause (stop hammering the service)

On 2026-10-09 the app made ~850 failed requests after the daily quota was gone.

- On a `quota` error, translation pauses until the reset time MyMemory reports
  ("NEXT AVAILABLE IN 5 HOURS 12 MINUTES…"). If no time is given, pause for 10 minutes.
  After the pause, the next message tries again.
- During the pause no requests are sent. Chat lines are still displayed with
  `[not translated – daily limit reached]`.
- One notice per pause in the chat (not per line), including the approximate reset
  time and — if no email is configured — the tip to add one.
- The status bar shows `Translation paused – free daily limit reached (until ~HH:MM)`.

## 4. Email for a higher limit — in Settings

`mymemory_email` already exists but could only be edited in `settings.json`.

- New Settings group **Translation Service**: email field, Save / Clear buttons, a hint
  ("Optional. Raises the free MyMemory limit from 5,000 to 50,000 characters/day. Use
  your own address; it is stored only in your local settings.json and sent only to
  MyMemory.").
- Basic format validation; an invalid value is rejected with a message, not saved.
- Saving an email ends a running quota pause (the new quota applies immediately).
- Default stays empty. Never pre-filled or shared.

## 5. Fewer requests without changing what is shown

- **Translation cache (default on):** successful translations are kept in memory
  (LRU, 1,000 entries, key = text + target language). Repeated lines ("gg", "o7",
  repeated trade spam) do not hit the API again. The output is identical — only the
  number of requests changes.
- **Nothing-to-translate skip (default on, strict rule):** text with **no letters at
  all** (numbers, punctuation, emoji, e.g. `200`, `+++`, `:)`) is not sent; the
  translation line shows the text unchanged — the same result MyMemory would return.
  Anything containing a letter of any script is still sent.

### Deliberately not done (caution about limiting content)

- **"Already in the target language" skip** based on the script (e.g. Cyrillic text
  with target `ru`): rejected — Ukrainian/Russian, Polish/English etc. share scripts,
  so it would silently leave messages untranslated.
- **Per-channel translation filter:** postponed to a later release as an opt-in
  feature (default: translate all channels; messages always displayed either way).
- **Fallback engines with user keys** (DeepL API Free, Microsoft Translator F0,
  LibreTranslate — all supported by the `translate` package): postponed, opt-in,
  needs its own design and testing.

## 8. Tests

New tests in `tests/test_translator.py`:
- error classification (429 HTTPError, MyMemory warning text, length limit, network,
  other) and reset-time parsing;
- quota pause: no API call during the pause, resumes afterwards;
- cache hit avoids a second API call; failures are not cached;
- no-letter text is not sent; text with letters is sent;
- legacy → new log-path migration only when the saved path is the legacy default;
- email validation.

Tests run with `USERPROFILE`/`LOCALAPPDATA` pointed at a temporary folder so the
developer's real settings are never touched.
